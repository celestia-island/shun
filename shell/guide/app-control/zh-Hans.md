# 启动被 Windows 应用控制拦下了

安装已经完成，失败的是启动：Windows 在执行文件之前就把它拦下了，程序报出 **os error 4551**，也就是 Windows 所说的 **0x11C7**。这两个数字说的是同一件事：**0x11C7** 是十六进制的状态码，**4551** 是它的十进制写法，文件都在磁盘上，一个也没少。

Windows 只运行它能识别的代码，或由受信任发布者签名的代码。在个人的 Windows 11 电脑上，这道闸门叫「智能应用控制」；在 Windows 10，或者受单位管理的电脑上，它是「应用控制（WDAC）」或 AppLocker。判定顺序也不复杂：先看云端信誉能不能给这个程序下结论，给不出结论再看它有没有有效签名，两样都没有就按「不受信任」拦下。

![智能应用控制开关的位置](guide/app-control-1.png)

## 找到这个开关

- **①** 打开**设置 → 隐私和安全性 → Windows 安全中心**，点**打开 Windows 安全中心**。
- **②** 进入**应用和浏览器控制**，再选**智能应用控制**。
- **③** 看它当前的状态：**开**会拦下未签名或无法识别的程序，**评估**只观察、不拦截，**关**什么都不拦。

![智能应用控制的三种状态](guide/app-control-2.png)

## 你自己电脑上的解法

如果状态是**开**，这次拦截就是智能应用控制做的：在同一处点**智能应用控制 → 设置**，把它改成**关**。对个人用户来说，这是唯一的开关。

微软把这一步写成单向操作：重新开启过去需要重置或重装 Windows；近期的 Windows 更新已能在 Windows 安全中心里直接重新开启，是否仍需重装，以你机器上的实际界面为准。

如果状态是**评估**或**关**，智能应用控制并没有拦任何东西，说明是别的策略在生效，请走下面的管理员部分。

![三条可走的路](guide/app-control-3.png)

## 如果开关由管理员掌管

单位或学校的电脑上，这个开关通常是灰的，或者根本不出现；Windows 10 更是完全没有智能应用控制。这时拦截来自一条策略——把错误码、程序的完整路径和下面的事件详情发给你们的管理员。他们可以把你的发布者证书加进策略，或单独为这一个文件加一条允许规则，也能告诉你这条策略是单位统一下发的，还是只在本机生效。

## 其他选择

- **要一份已签名的版本。** 这是唯一能保留应用控制的办法：微软建议开发者为程序做有效的代码签名，未签名的版本无论怎么装，在系统眼里都仍然「不受信任」。签名要覆盖安装包和真正被拦下的那个可执行文件。
- **「解除锁定」不是解法。** 右键 → 属性 → 解除锁定只会清掉「来自互联网」的标记，它不能覆盖应用控制策略。
- **没有单独的放行开关。** 微软明确说明，智能应用控制无法为某一个程序单独绕过，不必在设置里找把它加白的选项。

## 核对证据

事件查看器 → 应用程序和服务日志 → Microsoft → Windows → **CodeIntegrity → Operational**：**3077** 是强制策略下的拦截，**3076** 是同一事件在审核模式下的版本，**3033** 多指向被吊销或已过期的签名，但它有没有应用控制策略都可能出现，单凭它不能证明是应用控制拦的。脚本和 MSI 的拦截记在 **AppLocker → MSI and Script** 里。一条 3077／3076 都没有时，拦截可能来自别处，也可能只是没记进日志。
