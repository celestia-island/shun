# 啟動被 Windows 應用程式控制擋下了

安裝已經完成，失敗的是啟動：Windows 在執行檔案之前就把它擋下來，程式回報 **os error 4551**，也就是 Windows 所說的 **0x11C7**。這兩個數字是同一件事：**0x11C7** 是十六進位狀態碼，**4551** 是它的十進位寫法；檔案都在磁碟上，一個也沒少。

Windows 只執行它能辨識的程式碼，或由受信任發行者簽署的程式碼。在個人的 Windows 11 電腦上，這道關卡叫「智慧型應用程式控制」；在 Windows 10，或受組織管理的電腦上，它是「應用程式控制（WDAC）」或 AppLocker。判斷順序也簡單：先看雲端信譽能不能為這個程式下結論，下不了結論再看它有沒有有效簽章，兩者都沒有就當成「不受信任」擋下。

![智慧型應用程式控制開關的位置](guide/app-control-1.png)

## 找到這個開關

- **①** 開啟**設定 → 隱私權與安全性 → Windows 安全性**，點**開啟 Windows 安全性**。
- **②** 進入**應用程式與瀏覽器控制**，再選**智慧型應用程式控制**。
- **③** 看它目前的狀態：**開啟**會擋下未簽署或無法辨識的程式，**評估**只觀察、不阻擋，**關閉**什麼都不攔。

![智慧型應用程式控制的三種狀態](guide/app-control-2.png)

## 你自己電腦上的解法

如果狀態是**開啟**，這次阻擋就是智慧型應用程式控制做的：在同一處點**智慧型應用程式控制 → 設定**，把它改成**關閉**。對個人使用者來說，這是唯一的開關。

微軟把這一步寫成單向操作：重新開啟過去需要重設或重新安裝 Windows；近期的 Windows 更新已能在 Windows 安全性裡直接重新開啟，是否仍需重裝，以你電腦上的實際介面為準。

如果狀態是**評估**或**關閉**，智慧型應用程式控制並沒有擋下任何東西，代表是別的策略在生效，請看下面的系統管理員部分。

![三條可走的路](guide/app-control-3.png)

## 如果開關由系統管理員掌管

公司或學校的電腦上，這個開關通常是灰色的，或根本不會出現；Windows 10 更是完全沒有智慧型應用程式控制。這時阻擋來自一項策略——把錯誤碼、程式的完整路徑和下面的事件詳細資料發給你們的系統管理員。他們可以把你的發行者憑證加入策略，或單獨為這一個檔案新增允許規則，也能告訴你這項策略是組織統一派送的，還是只在這台電腦生效。

## 其他選擇

- **索取已簽署的版本。** 這是唯一能保留應用程式控制的辦法：微軟建議開發者為程式做有效的程式碼簽章，未簽署的版本無論怎麼安裝，在系統眼中仍然是「不受信任」。簽章要涵蓋安裝檔與真正被擋下的那個執行檔。
- **「解除封鎖」不是解法。** 右鍵 → 內容 → 解除封鎖只會清掉「來自網際網路」的標記，並不能覆寫應用程式控制策略。
- **沒有單獨的放行選項。** 微軟明確表示，智慧型應用程式控制無法為單一程式個別繞過，不必在設定裡找把它加入白名單的選項。

## 核對證據

事件檢視器 → 應用程式與服務記錄 → Microsoft → Windows → **CodeIntegrity → Operational**：**3077** 是強制策略下的阻擋，**3076** 是同一事件在稽核模式下的版本，**3033** 多半指向被撤銷或已過期的簽章，但有沒有應用程式控制策略都可能出現，單憑它無法證明是應用程式控制擋下的。指令碼與 MSI 的阻擋記在 **AppLocker → MSI and Script** 裡。完全沒有 3077／3076 時，阻擋可能來自別處，也可能只是沒留下記錄。
