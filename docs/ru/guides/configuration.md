# Справочник манифеста доставки

Поток доставки объявляется в собственном `Cargo.toml` приложения, в таблице
`[package.metadata.shun]` — шаблон cargo-deb / cargo-wix. Идентификация
продукта по умолчанию берётся из `[package]` (`name`, `version`); всё
остальное в таблице настраивает поток.

```toml
[package.metadata.shun]
product = "ShunDemo"                       # по умолчанию: имя пакета
publisher = "celestia-island"              # поле ARP Publisher
logo = "docs/logo.webp"                    # ресурс логотипа оболочки
payload = "examples/demo_payload"          # каталог, упаковываемый в артефакты
main-exe = "bin/shun-demo.exe"             # точка входа внутри payload

[[package.metadata.shun.attachments]]
key = "models"
title = "2D/3D model pack"
dest = "models"
[package.metadata.shun.attachments.online]
url = "https://example.test/models.shun"   # необязательное вложение (в lite-сборке скачивается при установке)

[package.metadata.shun.install]            # цель install (по умолчанию)
local = true                               # регистрируемая установка (ARP, деинсталлятор, ярлыки)
portable = true                            # портативный режим (маркер .shun-portable, без реестра)
portable-marker = ".shun-portable"          # имя файла-маркера для переносимых копий (переопределите, если приложение ищет свой)
desktop-shortcut = "ask"                   # always | never | ask (флажок мастера, по умолчанию включён; headless-запуски разрешают ask по наличию ярлыка)
start-menu-shortcut = "always"             # always | never | ask (по умолчанию always — спрашивают про ярлык на рабочем столе)
scope = "ask"                              # user (по умолчанию) | machine | ask
deep-links = ["shundemo"]                  # принадлежащие приложению схемы URL (myapp://…)
root-dir-folder = "ShunDemo"              # папка, подкладываемая под голым корнем диска (D:\ → D:\ShunDemo; по умолчанию — имя продукта)

[[package.metadata.shun.install.verbs]]    # команды контекстного меню (команды Проводника / действия рабочего стола)
key = "open-data"                          # стабильный id команды
display = "Open data folder"               # текст меню
target = "data-folder"                     # data-folder | uninstall | app
# arguments = "--safe"                     # только для цели app: дополнительные аргументы CLI

[package.metadata.shun.webview2]           # только Windows
type = "skip"                              # skip | evergreen-installer | fixed-version
# path = "WebView2Runtime"                 # fixed-version: распакованная папка рантайма
# silent-install = true                    # evergreen-installer: запустить bundled-
                                           #   установщик на машине без рантайма (по умолчанию —
                                           #   мастер сначала спрашивает согласие, headless
                                           #   запускает тихо)
# download-url = "https://…"               # evergreen-installer: если установщик не встроен, скачать
                                           #   его при установке (то же согласие, что и для
                                           #   встроенного установщика)
# warn-missing = true                      # skip / evergreen-installer: egui-фолбэк предупреждает
                                           #   в начале и в конце со ссылкой на официальную
                                           #   страницу загрузки Microsoft (по умолчанию)

[[package.metadata.shun.steps]]            # упорядоченный конвейер мастера (опционально)
columns = 2              # число колонок сетки режимов (по умолчанию — по одной на режим)
kind = "mode"                              # mode | scope | license | content | pairing | install
align = "center"                           # переопределение шага: center | start (по умолчанию от kind)

[[package.metadata.shun.steps]]
kind = "content"
title = "Release notes"                    # шаги content имеют заголовок…
markdown = "notes.md"                      # …и документ, встраиваемый при сборке

[[package.metadata.shun.steps]]
kind = "install"                           # ровно один шаг install

[package.metadata.shun.flash]              # цель flash (опционально)
require-removable = true                   # отказывать несъёмным устройствам
```

## Поля

| Поле | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `product` | string | `name` пакета | Заголовки, отображаемое имя ARP, метки flash |
| `publisher` | string | — | Поле Publisher в ARP |
| `logo` | path | — | Ресурс логотипа оболочки (относительно манифеста) |
| `payload` | path | — | Каталог, пакуемый в артефакты |
| `main-exe` | path | — | Точка входа относительно payload (цель ярлыка) |
| `install` | table | оба режима | переключатели `local` / `portable`, имя файла-маркера `portable-marker`, политики `desktop-shortcut` / `start-menu-shortcut` / `launch-after-install`, `default-dir` (замена расположения по умолчанию с раскрытием переменных окружения), `verbs`, `deep-links`, `aumid`, `icon`, `root-dir-folder` (папка, подкладываемая под голый корень диска, по умолчанию имя продукта) |
| `attachments` | массив таблиц | нет | необязательные сопутствующие ресурсы (паки ассетов): `key` / `title` / `dest` / `online.url`; lite-сборки скачивают их при установке |
| `update` | table | нет | слежение за обновлениями: `sources` (базовые URL зеркал, опрашиваются по порядку) + `files`, разрешаемые под первым доступным зеркалом |
| `webview2` | table | `skip` | стратегия рантайма Windows |
| `steps` | массив таблиц | конвейер по умолчанию | упорядоченный конвейер мастера (`mode`/`scope`/`license`/`content`/`pairing`/`install`, в любом порядке; ровно один `install`) |
| `script` | table | нет | хуки скриптов payload: `runner` + `hooks[]` (`phase`/`script`) — см. заметку о скриптинге |
| `variant` | массив таблиц | нет | именованные конфигурации артефактов, выбираемые флагом `shun build --variant` |
| `signing` | table | без подписи | профиль Authenticode / codesign, применяемый к артефактам |
| `license-sysl` | table | нет | бандл лицензии SySL + официальных переводов из её репозитория |
| `msix.logo-background` | цвет | `transparent` | Цвет подложки под прозрачным логотипом MSIX |
| `flash` | table | — | Объявляет цель flash |

## Политики ярлыков

`install.desktop-shortcut` и `install.start-menu-shortcut` разрешаются
по режиму запуска. Лица мастера показывают флажки (включённые по
умолчанию — конвенция NSIS); headless-режим (`--silent`) разрешает
`ask` по **наличию**: уже существующий ярлык обновляется на месте,
отсутствующий не создаётся. Тихое обновление никогда не должно
разбрасывать значки, которых пользователь не просил — эвристики AV/EDR
флагают именно это, а ярлык, удалённый пользователем, должен оставаться
удалённым. `always` / `never` фиксируют ответ в любом режиме; явные
флаги `--shortcut-desktop` / `--shortcut-menu` (контракт обновления)
перекрывают всё. Удаление убирает ярлыки безусловно.

## Запуск после установки

`install.launch-after-install` разрешает соглашение финальной
страницы: `ask` (по умолчанию) следует чекбоксу мастера — переключатель
NSIS «запустить после установки», в headless-запусках считается
отмеченным, — а `always` / `never` фиксируют его для оболочек без
такого переключателя.

Сам поток установки ничего не запускает. Оболочка вызывает
`shun::targets::install::launch` после успешного прохода: он запускает
настроенный `main-exe` внутри каталога установки в detached-режиме —
без ожидания, так что процесс установщика может завершиться сразу
после, — и ничего не делает, когда разрешённый
`InstallContext::launch_after_install` равен false или точка входа не
объявлена. Объявленная, но отсутствующая точка входа даёт обычную
ошибку `MissingEntry`.

## Защита от корня диска

Цель, являющаяся голым корнем файловой системы — выбранный диск вроде
`D:\` (также считаются `D:`, корень UNC-шары `\\server\share` и POSIX
`/`) — никогда не получает полезную нагрузку напрямую:
`InstallContext::apply_config` подкладывает под неё один уровень папки —
по умолчанию имя продукта, настраивается через
`install.root-dir-folder`. Мастера перезаписывают поле пути в момент
выбора или ввода корня, поэтому показываемое место назначения всегда
настоящее; headless-запуски `--dir=D:\` получают ту же защиту внутри
потока.

## Стратегии WebView2

| `type` | Несёт | Требует | Примечания |
| --- | --- | --- | --- |
| `skip` | ничего | системный WebView2 | Стандартный артефакт |
| `evergreen-installer` | офлайн-установщик Evergreen (~127 МБ) | повышение прав при установке | Регистрирует системный рантайм |
| `fixed-version` | распакованная папка рантайма | ничего | Одна приватная копия, разделяемая оболочкой и установленным приложением в режимах install и portable |

Замер (2026-09, v151 x64): рантайм fixed-version — **~293 МБ в сжатом
виде / ~661 МБ распакованным** — принятая цена, вровень с выводом других
пакеров. Артефакт встраивает ровно **одну** копию: оболочка
самозагружается, размещая поддерево рантайма из payload в
`%LOCALAPPDATA%\shun\<product>\webview2` и указывая
`WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` туда; распаковка учитывает хэши,
поэтому переустановки и заранее размещённые файлы подхватываются, а не
перезаписываются (события прогресса "Reusing") — второй копии того же
движка не возникает.

### Машины без рантайма

Лестница лиц никогда не умирает от отсутствия рантайма — она деградирует.
До разрешения лестницы оболочка зондирует рантайм вердиктом самого
загрузчика (`wry::webview_version()` — тот самый вызов, по которому
tauri пускает создание webview), поэтому битые остатки реестра больше
не отправляют webview-лицо в английскую коробку tauri "Could not find
the WebView2 Runtime":

- `evergreen-installer` + `silent-install` (по умолчанию `true`):
  приобретение рантайма живёт в шаге установки — инициализация только
  декодирует и размещает встроенный установщик (обнаруживается по
  префиксу `webview2/` payload) в кэш пользователя, и до разрешения
  лестницы лиц ничего не устанавливается. Запуск мастера сначала
  останавливается на вопросе согласия («Установить среду выполнения /
  Пропустить, только основная программа») и запускает приобретение
  лишь после разрешения — зримо, с собственным окном установщика и
  повышением через UAC, когда этого требует его манифест. Headless-путь
  держит `silent-install` как согласие и запускает установщик с
  `/silent /install`. Успешное приобретение обновляет машину на месте —
  загрузчик сообщает о рабочем рантайме, когда всё устаканится.
- Сборка без встроенного установщика, но с объявленным `download-url`
  скачивает установщик Evergreen с этого URL внутри того же шага
  установки, за тем же согласием (headless сохраняет регулятор
  `silent-install`) — lite-версия обновляет машину из сети, а не из
  собственного payload. Медленная или отсутствующая сеть никогда не
  блокирует первый UI: загрузка происходит внутри потока установки, а
  баннер деградации сообщает, что рантайм в пути.
- Как бы ни прошло, машина без рантайма получает лицо egui. При
  `warn-missing` (по умолчанию `true`) и без встроенного установщика
  это лицо предупреждает в начале и в конце мастера и встраивает ссылку
  на официальную страницу загрузки WebView2 от Microsoft. Оба
  регулятора отключаются по продукту:

```toml
[package.metadata.shun.webview2]
type = "evergreen-installer"
silent-install = false                  # никогда не запускать встроенный установщик
warn-missing = false                    # тихая деградация, без баннеров
```

Стоит знать об ограничении вверх по стеку: гейт рантайма tauri не
читает `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER`, поэтому машина только с
fixed-version (без установленного Evergreen) получает лицо egui, даже
если создание webview могло бы удаться — оболочка предпочитает лицо,
которое гарантированно отрисуется.

## Подложка логотипа MSIX

Windows подкладывает под логотип упакованного десктоп-приложения
системный синий по умолчанию (`#0078D7`) на каждой поверхности,
игнорирующей `BackgroundColor="transparent"` — диалог App Installer в
их числе. `msix.logo-background` принимает цвет `#RRGGBB`: CLI shun
компонует прозрачный логотип на него для ассетов пакета и объявляет
его как `BackgroundColor` — бренд сам выбирает цвет подложки везде:

```toml
[package.metadata.shun.msix]
# identity-name / publisher / display-name / executable ...
logo-background = "#0F172A"
```

## Офлайн-оболочка

Оболочка установки встраивает офлайн-UI на egui в дополнение к
webview-UI hikari. Им управляют тот же манифест и тот же payload (один
поток, три рендерера), эффектов он не рисует; выбирается он, когда в
Windows нет WebView2 (баннер прямо называет отсутствующую среду), либо
принуждается вручную:

```bash
shun-installer --no-webview   # тот же мастер, офлайн-рендерер (--fallback — старое написание)
```

Оба UI поддерживают офлайн-снимки — содержимое окна снимается через
`PrintWindow`, без автоматизации рабочего стола, и процесс завершается
после сохранения:

```bash
shun-installer --screenshot=ui.png                 # UI hikari (webview)
shun-installer --no-webview --screenshot=ui.png    # офлайн-UI egui
```

## Интерфейс оболочки

`[package.metadata.shun.shell]` (ключ `shell` в отдельном документе)
настраивает оболочку времени исполнения:

```toml
[shell]
timeline = "left"          # top (горизонтальная лента) | left (вертикальная слева)
log-level = "all"          # all (по умолчанию) | files | scripts | off
log-order = "newest"      # newest (по умолчанию, свежие сверху) | oldest (добавление в конец)
language = "auto"          # auto | en | zh-Hans | zh-Hant | ja | ko | fr | ru | es | de | pt
faces = ["webview", "egui", "tui"]  # лица, которые может показывать оболочка продукта (по умолчанию все три)

[shell.theme]
mode = "system"            # system | light | dark
accent = [34, 211, 238]    # каналы RGB — переопределяют --color-primary
```

`shell.faces` ограничивает лица, которые может показывать оболочка
этого продукта, — `webview` / `egui` / `tui`; отсутствие ключа = все
три. Headless-CLI (`--silent`, строка деинсталляции ARP) — субстрат,
его отключить нельзя. Запрос отключённого лица — ошибка; автоподбор
пропускает отключённые лица.

### Язык мастера

Мастер спрашивает язык на **первом шаге**: селектор со всеми десятью
поддерживаемыми локалями, каждая подписана на своём языке
(English, 简体中文, 日本語, ...). Переключение сразу перерисовывает
строки интерфейса и документы лицензии — соглашение следует выбранной
локали через `license-locales` / `locale-paths` — а выбор запоминается
для следующего запуска в файле пользовательских настроек
(`<локальные данные>/<продукт>/installer-prefs.json`, например
`%LOCALAPPDATA%\ShunDemo\installer-prefs.json` с содержимым
`{ "language": "zh-Hans" }`). Портативные запуски хранят выбор только
в памяти: переносимая копия не пишет никакого состояния системы.
`shell.language` остаётся фиксированной настройкой конфигурации —
запомненный выбор важнее неё, затем следует язык системы.

Выбранный язык попадает и в процесс установки: сценарии payload
получают его переменной окружения `SHUN_LANGUAGE`, и он записывается
в манифест установки на диске (его видят проходы ремонта/обновления).
Что именно записать в настройки самого установленного приложения,
решает сценарий payload — shun лишь экспортирует сам факт.

## Шаг сопряжения

Вид шага `pairing` запрашивает учётные данные для этой машины —
инверсная полоса: машина показывает код, оператор вводит его в панель
управления. Одна панель, две полосы:

```toml
[[package.metadata.shun.steps]]
kind = "pairing"

[package.metadata.shun.steps.pairing.source]
kind = "gateway"                     # gateway | scripts
official = "https://gateway.example.test"   # предвыбранный базовый URL шлюза
# allow-custom = true                # предлагать и ввод своего шлюза (по умолчанию)

[package.metadata.shun.steps.pairing.identity]
node-id = true                       # протокол шлюза индексируется по нему
name = false                         # необязательное имя устройства (предзаполнено hostname)
# tier = 1                           # уровень, выдаваемый при заявке, если продукт его фиксирует

# env-file = "pairing.env"           # полоса gateway: куда полученные учётные данные
                                     #   попадают внутри каталога установки (в стиле .env)
```

- `gateway` — встроенный JSON-RPC-клиент (`pairing.request` выпускает
  код, `pairing.await` ждёт в long-poll, `pairing.accept` доставляет
  учётные данные). Скриптовый рантайм на целевой машине не нужен;
  полоса требует `node-id` и `env-file`.
- `scripts` — собственная активация продукта: скрипты Python
  `request` / `await` / `record` относительно payload (`python3`, с
  откатом на `python`, если у хоста только имя без версии). Ответы
  панели приходят одним JSON-объектом на **stdin** скрипта — никогда
  через argv, — а stdout каждой фазы должен быть ровно одним
  JSON-значением; `record` сохраняет заявку (`env-file` переносится,
  но не потребляется). Каждая фаза идёт под дедлайном: зависший скрипт
  убивают, а не ждут.

## Источник payload

`[package.metadata.shun.source]` выбирает, откуда payload приходит при
установке:

```toml
[source]
type = "embedded"          # архив payload встроен в бинарник установщика
```

```toml
[source]
type = "online"            # установщик сам скачивает payload
url = "https://github.com/<org>/<repo>/releases/latest/download/ShunDemo.shun"
```

Онлайн-установщик выполняет **скачивание → распаковку → проверку** одним
проходом: приходящие байты сверяются с манифестом на лету, а события
прогресса сообщают о фазах скачивания и распаковки одновременно
(многослойный прогресс). Направьте `url` на ваш канал релизов (GitHub
Releases или любой HTTP-хост) — публикация нового пакета обновляет
установщик.

## Слежение за обновлениями

`[package.metadata.shun.update]` (ключ `update` в отдельном документе)
объявляет зеркала, которые оболочка опрашивает на предмет обновлений, и
файлы, разрешаемые под ними:

```toml
[update]
sources = [                                # базовые URL зеркал, пробуются по порядку
  "https://mirror.example.test/shun-demo",
  "https://releases.example.test/shun-demo",
]
files = ["latest", "app-setup.exe"]
```

Во время работы оболочка вызывает `shun::update::resolve`: каждое
зеркало получает короткую пробу (обычный GET первого файла, таймаут
10 с), первое, ответившее `200`, выигрывает весь проход, и каждый
объявленный файл разрешается в URL под победившей базой
(`<source>/<file>`). Недоступные и не-200 зеркала пропускаются с
предупреждениями; если не ответило ни одно — не разрешается ничего.
Затем оболочка сама забирает разрешённые URL — маркер версии `latest`
как текст (`fetch_text`), артефакты через онлайн-конвейер payload
(`OnlinePayload`: скачать → распаковать → проверить).

## Варианты сборки

`[[package.metadata.shun.variant]]` (единственное число — идиома
массива таблиц) объявляет именованные конфигурации артефактов, которые
выбирает флаг `shun build --variant <name>` — оси матрицы установщиков
(архитектура и ОС приходят из `--target`, ресурсные пакеты едут в
каталогах payload):

```toml
[[package.metadata.shun.variant]]
name = "lite"                        # id + суффикс имени артефакта
payload = "payload-lite"             # замена каталога payload
faces = ["egui", "tui"]              # замена лиц для оболочки варианта

[package.metadata.shun.variant.env]  # доходит до cargo-сборки оболочки
SHUN_FLAVOR = "lite"                 # (и её build.rs) — маркеры вкуса
```

Применение варианта подменяет каталог payload и список лиц оболочки;
`env` едет со сборкой оболочки, чтобы вкусы могли вшивать маркеры.
Неизвестное имя — ошибка.

## Подписывание кода

`[package.metadata.shun.signing]` настраивает подписывание собранных
артефактов — `shun build` подписывает установщик в конце прогона, а
`shun sign` подписывает отдельные файлы (оба пропускают с
`--no-sign`). Отсутствует = неподписанные артефакты, для локальных
тестов достаточно:

```toml
[package.metadata.shun.signing.windows]   # Authenticode через signtool
enabled = true
thumbprint = "<отпечаток сертификата>"    # выбор из хранилища пользователя/машины (/sha1)
# timestamp-url = "http://timestamp.digicert.com"   # RFC 3161 (/tr, значение по умолчанию)

[package.metadata.shun.signing.macos]     # codesign
enabled = true
identity = "<идентичность подписи>"
```

## Лицензия и пользовательские шаги

```toml
license = "docs/LICENSE.md"                # markdown, показывается на шаге лицензии

[license-locales]                          # лицензии по локалям
ru = "docs/LICENSE.ru.md"
en = "docs/LICENSE.en.md"

[[licenses]]                               # дополнительные документы лицензии
title = "Copyright notice"                 # необязательный заголовок над текстом
path = "NOTICE.md"                         # markdown, путь относительно манифеста
[licenses.locale-paths]                    # переопределения по локалям для документа
ru = "NOTICE.ru.md"

[[custom-steps]]                           # внедрение markdown-шага
key = "whats-new"
after = "license"
title = "What's New"
markdown = "docs/whats-new.md"
```

`license` + `license-locales` — одно-документный сахар; массив таблиц
`licenses` объявляет дополнительные документы, каждый с необязательным
`title` и собственными `locale-paths`. Обе формы объединяются: сначала
идёт документ-сахар, затем массив в порядке объявления. Совпадающий
путь локали (`license-locales` или `locale-paths`) имеет приоритет над
базовым документом. Шаг лицензии показывает по одному документу за раз
— при нескольких документах появляются кнопки «назад/вперёд» — а один
флажок согласия покрывает их все. В разрешённом JSON каждый документ
передаётся в `licenses` (title + body); унаследованная строка `body`
объединяет все тексты через строку-разделитель, поэтому рендереры,
читающие только `body`, по-прежнему показывают соглашение целиком.

Интерфейс поставляется с десятью локалями (`en`, `zh-Hans`, `zh-Hant`, `ja`,
`ko`, `fr`, `ru`, `es`, `de`, `pt`) и текстами по умолчанию; `shell.language = "auto"`
следует системе, фиксированная локаль закрепляет её, а по-локальные
переопределения лицензий сохраняют локализованные соглашения.

## Лицензия из репозитория SySL

`[package.metadata.shun.license-sysl]` при сборке бандлит Synthetic
Source License и её официальные переводы из собственного репозитория
лицензии (требуется feature `online`) — мастера показывают соглашение
на языке пользователя, не вендоря файлы лицензий:

```toml
[package.metadata.shun.license-sysl]
repo = "celestia-island/sysl"        # по умолчанию
branch = "main"                      # по умолчанию
locales = ["zh-Hans", "ja"]          # переводы для бандла (корневой английский входит всегда)
```

Теги локалей отображаются на i18n-каталоги репозитория sysl (`zh-Hans`
→ `zhs`, `zh-Hant` → `zht`; `ja`/`ko`/`fr`/`ru`/`es`/`de`/`pt`/`ar`
напрямую). Забандленные документы показываются на шаге лицензии как
любой другой документ лицензии.

## Хуки скриптов

`[package.metadata.shun.script]` объявляет скрипты-раннеры относительно
payload, которые поток доставки выполняет на границах фаз. Один раннер
на продукт — сегодня смонтирован только `duckscript` (встроенный
интерпретатор):

```toml
[package.metadata.shun.script]
runner = "duckscript"

[[package.metadata.shun.script.hooks]]
phase = "post-install"               # prepare | post-install | pre-uninstall
script = "scripts/post_install.ds"   # относительно payload, пакуется вместе с ним
```

Упавший хук валит весь поток. Полный контракт — фазы, окружение,
видимое хуками (`SHUN_LANGUAGE` в их числе), примеры — живёт в
[заметке о скриптинге](../design/scripting.md).
