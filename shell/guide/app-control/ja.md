# 起動が Windows のアプリ制御にブロックされました

インストールは完了しています。失敗したのは起動で、Windows が実行ファイルを走らせる前に止め、アプリは **os error 4551** を返しました。これは Windows が **0x11C7** と呼ぶブロックと同じものです。**0x11C7** は 16 進の状態コード、**4551** はその 10 進表記にあたります。ファイルはすべてディスク上にあり、欠けているものはありません。

Windows は、認識できるコードか、信頼された発行元が署名したコードしか実行しません。個人の Windows 11 ではこの関門が「スマート アプリ コントロール」、Windows 10 や組織で管理された PC では「アプリ制御 (WDAC)」または AppLocker がその役目を負います。判定は単純です。まずクラウドの評価で安全性を判断し、判断できなければ有効な署名があるかを見て、どちらもなければ「信頼されていない」としてブロックします。

![スマート アプリ コントロールのスイッチの場所](guide/app-control-1.png)

## スイッチの場所

- **①** **設定 → プライバシーとセキュリティ → Windows セキュリティ**を開き、**Windows セキュリティを開く**をクリックします。
- **②** **アプリとブラウザー コントロール**を選び、続いて**スマート アプリ コントロール**を開きます。
- **③** 表示されている状態を確認します。**オン**は未署名・未認識のアプリをブロックし、**評価**は観察だけでブロックせず、**オフ**は何も制限しません。

![スマート アプリ コントロールの 3 つの状態](guide/app-control-2.png)

## 自分の PC での対処

状態が**オン**なら、このブロックはスマート アプリ コントロールによるものです。同じ画面で**スマート アプリ コントロール → 設定**を開き、**オフ**に切り替えてください。個人利用で選べる手段はこれだけです。

ただし Microsoft はこれを一方向の操作と説明しています。以前は元に戻すのに Windows のリセットか再インストールが必要でしたが、最近の更新では Windows セキュリティ内から再び有効にできます。実際の画面が優先です。

状態が**評価**または**オフ**なら、スマート アプリ コントロールは何も止めていません。別のポリシーが効いているので、下の管理者向けの手順へ進んでください。

![先に進む 3 つの道](guide/app-control-3.png)

## 設定が管理者の管轄にある場合

職場や学校の PC ではスイッチが灰色か、そもそも表示されません。Windows 10 にはスマート アプリ コントロール自体がありません。その場合のブロックはポリシーによるものなので、エラー コード、実行ファイルのフル パス、下記のイベント情報を管理者に送ってください。管理者は発行元の証明書をポリシーに追加するか、この 1 ファイルだけの許可規則を作れます。

## ほかに選べる手段

- **署名済みのビルドを入手する。** アプリ制御を有効のまま解決できる唯一の方法です。Microsoft は有効な証明書での署名を開発者に求めています。未署名のビルドは、どうインストールしても「信頼されていない」ままです。署名はインストーラーと、実際にブロックされた実行ファイルの両方を対象にしてください。
- **「ブロックの解除」は解決策ではありません。** 右クリック → プロパティ → ブロックの解除は「インターネットから取得した」という印を消すだけで、アプリ制御ポリシーを上書きはしません。
- **アプリ単位の許可設定はありません。** Microsoft は、スマート アプリ コントロールを 1 つのアプリだけ例外にすることはできないと明言しています。設定を探しても見つかりません。

## 証拠を確認する

イベント ビューアー → アプリケーションとサービス ログ → Microsoft → Windows → **CodeIntegrity → Operational**:**3077** は強制ポリシーによるブロック、**3076** はその監査モード版です。**3033** は失効・期限切れの署名を指すことが多いものの、アプリ制御ポリシーがなくても記録され得るため、これだけで原因と断定はできません。スクリプトと MSI のブロックは **AppLocker → MSI and Script** に記録されます。3077 も 3076 もない場合は、ブロック元が別にあるか、単にログに残っていない可能性があります。

原因を取り除いたうえで、インストーラーに戻って**インストール完了**をもう一度押してください。インストーラーを閉じてしまった場合は、インストール先フォルダーからアプリを起動できます。**0x11C7** と **os error 4551**、スイッチの状態、確認したイベント ID を開発者に送れば、ポリシーによるブロックかインストールの破損かを切り分けられます。
